# Settings that need an apply group and are not in one yet. A key is added here only
# by the scan's own finding, check-apply-groups.sh, or by the hand reading in
# bugsV5/settings-eval, and leaves the list in the commit that gives it a group; the
# list is empty when the project is done and goes with the code that reads it.
#
# Columns, tab between: key, the stream that moves it, why it is listed.
#   scan  every read of the setting is a change notifier, an action branch of an exec
#         or startup, which is what the scan asks a group for. The scan fails when
#         such a key is not listed, and when one listed this way no longer is
#         one, since an allowance with no reason left is what hides the next gap.
#   eval  the setting is read by a helper both the notifier and the startup call to
#         push it on, or at the moment a screen opens, and the scan cannot tell
#         that from a read where it is used. The hand reading found that a change
#         does nothing until the next start. Only a move into a group takes it off.
#
# Streams are those of the plan: T6 the video pilot, S1 misc and network, S2 OSD,
# S3 audio and CEC, S4 recording, HDD, zapit and web channels, S5 weather, LCD4L,
# GLCD, VFD and plugins, S6 activation-only screens, CAM and update, S7 key
# bindings, player and OSD language.
